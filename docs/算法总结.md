# 五线多头排列选股：算法总结与踩坑记录

> 代码在 `src/alignment.py`，测试在 `tests/test_alignment.py`，
> 原 notebook 的三个版本在 `legacy/`。
> 本文只讨论方法，不构成投资建议。

---

## 1. 这个因子想抓什么

「五线多头排列」是 A 股最常用的均线选股条件之一：MA5、MA10、MA20、MA30、MA60
从上到下依次排开，短均线在长均线之上，代表不同周期的持仓成本同时抬升。

但单纯的排列会选到**已经涨完的票**——五线排列得越漂亮，往往意味着涨幅越大。
所以原始 notebook 加了一条反向约束：**10 日涨幅必须小于 15%**。

这条约束是这个因子的核心：

```
排列告诉你趋势已经建立  →  涨幅上限告诉你趋势还没走完
```

用一句话概括：**买在趋势的中段，不买在启动前，也不追在加速后。**
notebook 的文件名叫「追涨中段因子」，说的就是这件事。

## 2. 五个条件的形式化

记收盘价序列为 $c_1,\dots,c_T$，窗口 $w$ 的简单均线为

$$
MA_w(t)=\frac{1}{w}\sum_{i=0}^{w-1}c_{t-i}
$$

五个条件：

| # | 条件 | 表达式 | 含义 |
|---|---|---|---|
| 1 | 五线多头 | $MA_5>MA_{10}>MA_{20}>MA_{30}>MA_{60}$ | 各周期成本依次抬升 |
| 2 | 站上 MA10 | $c_t \ge MA_{10}(t)$ | 价格没有跌破中期均线 |
| 3 | 斜率多头 | $\Delta MA_w(t)>0$，且 $\Delta MA_5>\Delta MA_{10}>\dots>\Delta MA_{60}$ | 全部向上，且短周期加速 |
| 4 | 涨幅未透支 | $c_t/c_{t-10}-1<15\%$ | 不追末段 |
| 5 | 量能放大 | $V_t>1.5\cdot\overline{V}_{t-5:t-1}$ 且 $>1.5\cdot\overline{V}_{t-10:t-2}$ | 有增量资金 |

其中 $\Delta MA_w(t)=MA_w(t)-MA_w(t-1)$。

### 条件 3 的含义

斜率的严格递减链（$\Delta MA_5>\Delta MA_{10}>\dots$）要求**短周期涨得比长周期快**，
也就是趋势在加速。这不是「多头排列」的必然结果：

- 指数型上涨（每天 +0.35%）满足；
- **线性上涨（每天 +0.5 元）不满足**——所有窗口的斜率完全相同。

这一点在原始实现里变成了一个真实的 bug，见 §4.1。

### 条件 4 是「中段」的来源

10 日涨幅 15%，对应年化约 40 倍，看起来很高。但 A 股短线的加速段很陡：
连续 10 个涨停就是 159%。15% 的阈值把「已经进入加速段」的股票挡在外面，
留下的是斜率温和、结构完整的部分。

阈值没有经过拟合，来自经验。降低它会更保守（更早），提高它会更激进（更晚）。

## 3. 三个版本：严格 AND、评分、评分 + 缓存

notebook 的四个代码单元格是同一策略的三次迭代：

| 版本 | 判定 | 输出 | 问题 |
|---|---|---|---|
| v1 严格 AND | `cond1 and cond2 and cond3 and cond4 and cond5` | 只输出全满足 | 线性趋势被斜率链误杀 |
| v2 评分 | 每个条件 +10，满分 50 | **得分 > 0 就输出** | 评分类别取代了 AND，横盘股也能上榜 |
| v3 评分 + 缓存 | 同 v2，`_load_processed_codes` 多一个空集合保护 | 同 v2，打印前 50 | 同 v2，且缓存不区分日期 |

v2 的改动看起来是「让结果更丰富」，实际上改变了因子的定义。

五个条件是**合取**关系：条件 4 的作用是排除末段，单独满足它没有任何选股意义。
把判定换成「满足几条」，等于允许只满足条件 4 的股票进入结果：

```python
# v2 / v3
if res['score'] > 0:          # 一只横盘股：条件4 + 条件5 = 20 分，入选
    return output
```

实验市场里的例子：横盘震荡的 `Chop` 得分 30，顶部回落的 `Top rollover` 得分 20，
都会进入「按得分排序」的结果表。它们没有一条均线是向上的。

**正确的用法是：先做门控，再用得分排序。**
本仓库的 `select()` 只返回五条全满足的股票，得分只用于在入选集合内部排序
（同分时优先 10 日涨幅更小的）。

## 4. 五个隐藏缺陷

这五个问题的共同点是：**不报错，输出看起来完全正常。**

### 4.1 严格斜率链会拒绝一条完美的直线

原始代码：

```python
slopes = [latest[f'ma{w}'] - prev[f'ma{w}'] for w in self.ma_windows]
cond3 = all(s > 0 for s in slopes) and all(
    slopes[i] > slopes[i + 1] for i in range(len(slopes) - 1)
)
```

构造一条每天上涨 0.5 元的直线，截至第 160 天：

```
MA5   = 148.50   MA5 斜率  = 0.5
MA10  = 147.25   MA10 斜率 = 0.5
MA20  = 144.75   MA20 斜率 = 0.5
MA30  = 142.25   MA30 斜率 = 0.5
MA60  = 134.75   MA60 斜率 = 0.5
```

`0.5 > 0.5` 为假，条件 3 不成立。**这是最健康的一种趋势，被斜率链判成了不合格。**

更麻烦的是浮点噪声。如果价格序列不是精确的二进制小数，五个斜率会相差
$10^{-15}$ 量级，`>` 的结果取决于累加顺序——同一只股票今天被选中、明天不被选中，
而数据没有任何变化。

修复：比较时允许价格尺度上的容差，把「严格递减」放宽为「不递增」：

```python
eps = 1e-9 * max(1.0, abs(close))
rising = all(s > eps for s in slopes) and all(
    slopes[i] + eps >= slopes[i + 1] for i in range(len(slopes) - 1)
)
```

`docs` 里的演示市场，`Linear ramp` 在 v1 中被拒绝，在本实现中得 50 分入选。
测试：`test_linear_ramp_is_selected_here`、`test_legacy_strict_order_rejects_the_linear_ramp`。

### 4.2 量能基线把当日算进去了

原始代码：

```python
df['vol_ma5'] = self.MA(df['volume'], 5)
cond5 = latest['volume'] > latest['vol_ma5']
```

`vol_ma5` 是最近 5 天的均值，**包含今天**。设今天成交量为 $v$，前 4 天均值为 $m_4$：

$$
v>\frac{v+4m_4}{5}\iff 5v>v+4m_4\iff v>m_4
$$

也就是说，条件 5 实际等价于「**今天比前 4 天的均值高一点点**」，而不是「放量」。
前 4 天都是 100 万手，今天 101 万手就能通过。10 日均量同理，等价于前 9 日均值。

修复分两步：

1. 基线**不含当日**，即 $\overline{V}_{t-w:t-1}$；
2. 把倍数做成参数 `volume_ratio`，默认 1.5，恢复「放量」的本意。

```python
prior = volumes[-1 - w:-1]
base = math.fsum(prior) / w
ok = volume > config.volume_ratio * base
```

测试：`test_volume_baseline_excludes_today`（恰好 1.5 倍不通过，1.5001 倍通过）。

### 4.3 不复权价格 + 60 日均线

原始代码：

```python
bs.query_history_k_data_plus(..., frequency="d", adjustflag="3")
```

`adjustflag="3"` 是不复权。用它算 MA60 和 10 日涨幅，会遇到两类公司行为：

- **送转**：3 送 1 当天价格除以 1.3，MA60 跨过除权日时出现断崖，五线排列被破坏；
- **分红**：除息日价格下跳，10 日涨幅被压低，本来已经透支的股票反而通过了条件 4。

演示市场的 `3:1 split (raw)` 就是这个场景：原始序列在最后 20 天前从 60 元跳到 20 元，
MA5 在 22 元附近、MA60 在 45 元附近，条件 1 失败；把同一段历史按 3:1 前复权后，
它是一条干净的趋势，五条全过。

修复：默认 `adjustflag="2"`（前复权），只对**因子计算**使用复权价。
前复权以查询区间的最后一天为基准，因此同一天内计算是自洽的；跨日比较时历史价格会整体平移，
这一点在 §9 说明。

### 4.4 断点缓存不区分日期

原始代码的文件名是固定的：

```python
checkpoint_file = 'checkpoint.csv'
processed_file = 'processed_codes.csv'
```

`batch_analyze` 从这两个文件恢复「已处理代码」，然后

```python
remaining_codes = [c for c in stock_codes if c not in processed_codes]
```

第二天用默认参数再跑一次：所有代码都在 `processed_codes` 里，`remaining_codes` 为空，
程序**一只股票都不请求**，直接把昨天的 `checkpoint.csv` 读出来、
排序、写成以今天时间戳命名的新 CSV 并打印。

日志显示「共 5000 只，已处理 5000 只，剩余 0 只」，没有任何警告。
输出文件的名字是今天的，里面的 `分析日期` 是昨天的。

修复：

```python
checkpoint_path(cache_dir, date)   # checkpoint_2026-11-10.csv
processed_path(cache_dir, date)    # processed_2026-11-10.csv
reusable_rows(rows, date)          # 丢弃 分析日期 != date 的行
```

行级校验比文件名更可靠：即使有人手动合并了缓存，日期不匹配的行也不会被复用。
另外，如果某只股票停牌，最后一根 K 线的日期不是请求日，verdict 会标记 `stale=True`
并在日志里说明，而不是假装今天有数据。

测试：`test_previous_day_rows_are_not_reused`、
`test_a_suspended_stock_cannot_report_yesterdays_close_as_today`。

### 4.5 评分制丢掉了合取

§3 已经说明。补充一个实现细节：v1 在保存时做了 `drop_duplicates(subset=['股票代码'])`，
v2/v3 删掉了这一步。如果输入池里有重复代码（很常见），
`remaining_codes` 会在开始时一次性算出，两条重复项都会进入循环、都产生结果，
最终 CSV 里同一只股票出现两行。

修复在入口：`normalize_codes()` 保序去重。测试：`test_normalize_codes_prefixes_and_dedupes`。

### 4.6 次要问题

- **停牌日的零成交量**：如果数据源把停牌日返回为 `volume=0`，量能基线会被拉低，
  任何一天都算「放量」。本实现遇到基线中非正的成交量直接判定条件 5 不成立，
  并给出 `volume_baseline_unusable` 原因。
- **`func_timeout` 的线程**：它用线程实现超时，超时后调用方抛异常，
  但工作线程仍可能在后台持有 baostock 会话。连续超时会累积线程和连接。
  这是原实现的实用缺陷，本仓库保留 `func_timeout` 以兼容原行为，但在文档中标注。
- **每只入选股票额外查一次名称**：`get_stock_name` 在 `_process_one_stock` 内调用，
  对入选股票多一次网络往返。本实现从股票池 CSV 读取名称，没有名称时才查询。
- **可变默认参数** `ma_windows=[5, 10, 20, 30, 60]`：没有在方法内修改，因此没有实际后果，
  但仍是应当避免的写法。

## 5. 参数表

| 参数 | 默认值 | 作用 | 调整方向 |
|---|---|---|---|
| `ma_windows` | `(5, 10, 20, 30, 60)` | 均线周期 | 缩短整体周期会更灵敏，噪声也更多 |
| `max_rise` | `0.15` | 10 日涨幅上限 | 降低 → 更早、更保守；提高 → 更晚、更激进 |
| `rise_lookback` | `10` | 涨幅回看天数 | 与 `max_rise` 一起决定「中段」的位置 |
| `volume_windows` | `(5, 10)` | 量能基线窗口 | 只用 5 日更敏感，只用 10 日更平滑 |
| `volume_ratio` | `1.5` | 放量倍数 | 1.0 约等于原实现的实际阈值；1.5–2.0 更严格 |
| `rel_tolerance` | `1e-9` | 价格尺度容差 | 一般不需要改 |

`min_history = max(max(ma_windows) + 1, rise_lookback + 1, max(volume_windows) + 1)`，
默认 61 根。少于这个数量直接拒绝，并给出原因，而不是静默返回 0 分。

## 6. 计算过程

对每只股票：

```
日线（前复权） ──► 5 条均线（增量求和） ──► 当日/昨日值 ──► 斜率
                                                      │
     ┌────────────────────────────────────────────────┘
     ▼
条件1 排列  ─┐
条件2 MA10  ─┤
条件3 斜率  ─┼──► 5 个布尔值 ──► 得分 = 10 × 满足数
条件4 涨幅  ─┤                     │
条件5 量能  ─┘                     ▼
                              五条全真 → 入选
                              否则 → 记录失败原因
```

均线用增量求和而不是每天重算窗口：

```python
total = math.fsum(values[:window])
out[window - 1] = total / window
for i in range(window, len(values)):
    total += values[i] - values[i - window]
    out[i] = total / window
```

复杂度从 $O(T\cdot W)$ 降到 $O(T)$。5 条均线、150 根 K 线、5000 只股票：
约 375 万次浮点运算，Python 里不到 2 秒。实际耗时几乎全部在网络。

`math.fsum` 用于第一个窗口，减少长序列的累加误差；之后的增量更新误差在
$10^{-12}$ 量级，远低于价格容差。

## 7. 数据管道

```
stock_pool.csv ──► normalize_codes ──► 逐只拉取（重试/重连/超时）
                                              │
                                              ▼
                                     evaluate(bars, config)
                                              │
                          ┌───────────────────┴───────────────────┐
                          ▼                                       ▼
                  入选 → 当日 checkpoint                   未入选 → 只留原因
                          │
                          ▼
              output/五线多头_{date}_{timestamp}.csv
```

容错要点：

- 登录后先做一次 `query_trade_dates` 预热，避免「登录成功但首个请求为空」；
- 错误信息包含 `login / session / expired / 未登录 / 令牌` 时重新登录；
- 网络异常按 `2**attempt` 退避，最多重连 2 次；
- 单只股票 8 秒超时（`func_timeout`），一只卡住不影响整批；
- 每 20 只写一次检查点；已处理代码按日记录，进程中断后可以续跑；
- 最后写入的 CSV 只包含入选股票，并带 `未满足条件` 列，便于复盘为什么没选。

## 9. 局限

1. **没有回测。** 本文所有阈值来自交易经验，没有做参数搜索，也没有收益曲线。
   把输出直接接到下单接口是灾难。
2. **前复权的基准随查询日移动。** 同一天内自洽，跨日比较历史价格会整体平移，
   回测时必须统一基准。
3. **成交量没有复权。** 送转后成交股数会跳变，量能比值在除权日附近失真。
4. **没有流动性过滤。** 日成交额 100 万元的股票和 10 亿元的股票一视同仁。
   这是最值得优先补的一项。
5. **没有行业约束。** 板块整体启动时，同行业会一次选出十几只高度相关的股票。
6. **幸存者偏差。** 股票池是当前上市的代码，退市和长期停牌的样本不在其中。
7. **没有退出规则。** 这是一个截面筛选器，不是完整策略。
8. **涨幅上限的边界是浮点比较。** `115/100 - 1` 在双精度下是 `0.1499999...`，
   恰好 15% 的情况会通过。影响很小，但写清楚比假装精确好。
9. **停牌、涨跌停、竞价数据都没有处理。** 一字板当天的成交量极小，均线和量能都会失真。

---

## 10. 可以继续做的

1. **流动性门槛**：近 20 日日均成交额、换手率下限。
2. **复权成交量**：按复权因子调整成交量，或在除权日前后跳过量能条件。
3. **截面标准化**：把斜率除以价格（相对斜率），让不同价位的股票可比。
4. **前向收益评估**：按入选日 T+5/T+10 的收益做分组检验，而不是只数入选数量。
5. **行业上限**：同一行业最多取 N 只，降低组合的相关性。
6. **增量更新**：只拉取新增交易日，维护本地日线库。
